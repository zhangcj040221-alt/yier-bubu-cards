# 一二布布卡牌批量素材规范 v0.1

## 每张卡的资产层
- character.png / character.webp：已通过原作还原度验收的透明角色，RGBA，建议至少 1024×1280；轮廓、比例、五官必须保持基准一致。
- background.webp：**不含角色**的主题背景，建议至少 1200×1700。
- foreground.webp：可选，遮挡人物的前景道具，可形成 2.5D 视差。
- fx-mask.png：可选，控制局部光泽/闪点而不是把所有部位同样打亮。
- poster.webp：可选，静态分享/加载封面，不能代替完整分层。

## 共享层
- src/engine/CardViewer.js：视角、场景、灯光、图层、资源装配。
- src/engine/foil.js：整张卡面镀闪 Shader，可通过强度和遮罩参数改品质。
- assets/shared/：通用边框、光纹、粒子、法线图、UI 资源。**不按单卡重复制作**。
- src/catalog.js：每张卡的数据，未来可以从 JSON / 管理工具生成。

## 视觉和授权要求
1. 镀闪在卡面，不等于彩虹水晶外框；金色框体与膜层分离。
2. 优先保留布布/一二已经确认的原作轮廓、比例、领结等设定。不要因镀闪或所谓 3D 感重绘成不同角色。
3. 动作遵循原版 GIF 的动作逻辑，不用生硬的整体上下起伏代替表演。
4. 现有 character.svg 是程序工程**占位稿**，**不是已确认原画**。收到高质量透明原画后直接更换素材路径。
5. 对外展示前检查权利来源，区分原作素材、授权素材、二创与临时 AI 草图。

## 新卡制作流程
确认素材合法及原画品质 → 按唯一 card id 保存切层图片 → 新增 catalog 配置 → 预览多机型 → 图像/动作/材质验收。不要为了每一张卡复制 Shader 或 Three.js 初始化代码。

## 迭代计划
1. 导入原作透明 PNG，支持独立背景/前景资源路径。
2. 增加局部镀闪 mask、统一边框预设、动态光照质量档。
3. 按原作 GIF 开发可配置动作模块，单独提供动作数据而非写死在角色代码里。
4. 批量卡牌列表、截图导出、自动质量检查与素材授权台账。
